# 静态卡片缩略图与单个实时预览

下述缩略图提速优化已于 2026-11-04 部署，文末记录本次备份、运行环境与线上验收结果。

## 行为

普通卡片使用 640 像素宽的 WebP 缩略图，不创建 iframe。列表返回已就绪图片的版本号，前端直接加载图片，浏览器延迟加载、异步解码；缺少图片的卡片接近视口后才查询状态。图片加载与排队生成使用不同提示。聚焦卡片时才创建其网页 iframe；切换卡片、收起或离开页面时卸载。不同列表通过共享焦点事件保持整个页面最多一个实时预览；标签页进入后台时也卸载，回到前台后恢复当前聚焦作品。

简介、评论、操作按钮和展开动画沿用现有交互。隐藏作品不请求缩略图或加载实时预览。缩略图不存在、生成失败或队列繁忙时显示占位图，不回退到额外的实时网页。

## 缓存和生成

- `GET /api/previews/:slug/thumbnail`：公开可访问作品的缩略图状态。已就绪返回 200 和版本号；排队返回 202；暂不可生成返回 503。元数据不缓存。
- `GET /api/previews/:slug/thumbnail/image?version=...`：返回 WebP，每次重验作品可见性与版本，使用 ETag。隐藏、删除或到期作品返回 404，旧版本 URL 返回 409。
- 版本由作品当前根目录、入口文件修改时间及大小计算。重新上传或回退后会使用对应版本的图片；更新事件会让当前页面重新请求。
- 图片保存在 `server/storage/.thumbnails` 下，每个作品只保留一版成功的缓存。它们属于可重建缓存，可在停写截图任务后清理；现有上传文件不改写。
- 上传、批量上传、文件更新与回退在持久化成功后触发后台准备，不等待图片生成才返回响应。
- 服务监听成功后按 ID 分页补齐现有公开作品（每页 50 条，每条等待共享队列清空），完成后每 5 分钟再检查一次；缓存命中直接跳过，失败版本冷却 5 分钟。上传、可视卡片和补齐任务共享串行队列，最多 40 个待处理任务，不会并发启动截图浏览器。
- 已有 PNG 优先在同一队列内直接压缩为 WebP，无需重开网页。保留入口版本计算方式，WebP 使用新的 ETag 前缀，避免旧 PNG 浏览器缓存错误地返回 304。发布成功后删除该作品旧缓存。
- 截图仍以 1200×760 获取桌面排版，再缩至 640 像素宽，WebP 质量 72。sharp 禁用原生缓存、使用单个处理线程；不会将页面改成手机布局。
- 前置页面可用性检查最多 3 秒，单次浏览器任务限时 12 秒。同版本请求合并；客户端先每 3 秒查询，10 次后改为每 10 秒，最多 120 次，避免排队稍长便误报无图。成功元数据在当前页面短期复用（最多 100 项、有效 60 秒），收起卡片无需重复查询。
- 截图通过固定站点地址 `/p/:slug/?preview=1` 获取，不计作品访问次数，不接受请求者指定任意渲染 URL。生成后再次核对作品版本，变化时不发布该截图。

## 运行环境

本次优化新增固定版本 `sharp@0.34.5`，锁文件核对未变更既有依赖的版本；无需数据库迁移。部署时需先在独立暂存目录按锁文件安装并验证 Linux 原生压缩依赖，再更新发布文件。不要将 Windows 的 node_modules 复制到生产环境。需要一个独立安装的 Chrome/Chromium 可执行文件，可通过 `THUMBNAIL_BROWSER_PATH` 指定。Windows 默认尝试本机 Chrome/Edge；Linux 默认识别 Chrome、Chromium 和 OpenCloudOS 的无界面 Chromium 路径。

每次截图使用临时浏览器资料目录、无登录状态、最小环境变量，并在结束后清理。不会把应用凭据传给浏览器。Linux 应用若以 root 运行，截图进程会降为 UID/GID 65534，保留 Chromium 沙箱；系统需支持相应沙箱。运行环境不满足时生成失败并返回占位图，不使用 `--no-sandbox`。

截图浏览器使用临时网络代理，允许选定作品的 HTTP 路径及解析到公网 IPv4 的外部素材；拒绝其他内网、回环、云元数据地址及非公网 TLS 隧道，DNS 结果固定到实际连接地址。禁用绕过代理的 QUIC、非代理 UDP 和 WebSocket 升级。仅有 IPv6 或依赖 WebSocket 的外部素材可能不能完整呈现在缩略图中，不影响用户打开原作品。

2026-11-04 用户明确要求部署。服务器内存约 1.6 GB，因此保留串行截图并缓存结果；生产已安装并验证无界面 Chromium 与中文字体，发布已完成。后续资源紧张时宜将渲染放在单独环境，而非增加主应用内的并发浏览器。部署须完整备份数据库、上传文件和当前版本，并保留 `.env` 与 `storage`。

## 个人控制台聚焦预览越界修复（已发布）

根因是控制台第 3n+2、3n+3 张普通卡片的 aspect-ratio 选择器优先级高于展开态重置规则，导致展开后仍保留 3:2 或 1:1 比例。当右侧内容较高时，左侧预览按该比例计算的宽度可能超出自身网格列，遮盖右侧信息和按钮。

将控制台三种缩略图比例明确限定到未展开卡片，展开态统一使用原有 auto 比例和网格尺寸。未添加额外宽度补丁，普通卡片比例保持不变。
